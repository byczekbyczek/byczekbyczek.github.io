Windows development alpha · explicit one-shot capture + file fallback

Turn a loading screen into clearer team context.

BlitzPredict captures one frame from an explicitly selected World of Tanks Blitz game window or accepts a JPG, PNG, or WebP loading-screen image. It recognizes both compact preferential and wider standard 7v7 rosters, resolves player identities conservatively through the official Wargaming API, and renders an exportable tactical HUD.

Explore the current build → Review the evidence

Capture is user-triggered, window-only, and one-shot. Continuous watching, automatic battle detection, a live overlay, input hooks, gameplay automation, a hosted backend, and public distribution are not part of the current build.

Built today

A working local application, not a notebook-only concept.

The original experiment has been extracted into an importable Python package with reusable services, a command-line workflow, a Windows desktop interface, deterministic tests, and an internally validated portable build path.

01

Desktop GUI and CLI

The GUI can capture one frame from an explicitly selected game window or use a JPG, PNG, or WebP fallback. Analysis stays in a background worker, while the file-based command-line path remains available.

02

Adaptive 7v7 geometry

A shared planner supports compact preferential and wider standard rosters, preserves source aspect ratio, and retains a contour fallback for unfamiliar screens.

03

Local nickname OCR

EasyOCR reads row crops produced by the same geometry plan used across production analysis and controlled development audits.

04

Conservative identity trust

Only a unique, case-insensitive exact nickname match contributes statistics. Corrected, fuzzy, saturated, duplicated, or ambiguous results abstain instead of silently misattributing a player.

05

Managed Wargaming access

Official public API calls use run-local caching, bounded retries, conservative pacing, batched account information, and account-ID keyed joins.

06

HUD and honest diagnostics

The renderer keeps failed or uncertain rows visible, reports the trusted sample size, and exposes aggregate progress without nicknames, IDs, paths, coordinates, or image content.

Current pipeline

One local flow with explicit trust boundaries.

Geometry and OCR happen locally. Player statistics are requested only for identities that pass the exact-match safety contract.

01 / INPUTSelected window or file

One user-triggered game-window frame or a manually selected loading-screen image.

02 / PLANRoster geometry

Normalize, identify the layout, and produce 14 row crops.

03 / READLocal OCR

Extract nickname candidates with deterministic preprocessing.

04 / TRUSTExact identity

Reject uncertain or ambiguous account resolution.

05 / FETCHPublic statistics

Use managed requests to the official Wargaming API.

06 / OUTPUTRender and export

Build the HUD, preview it, and save the result.

Local: source image, geometry, OCR, result construction, rendering. Network: official Wargaming endpoints for trusted account and statistics requests.

Architecture boundary

The local core exists. Production delivery remains a separate decision.

The current application does not depend on a BlitzPredict cloud backend. A hosted service should be introduced only if a controlled pilot shows that it is necessary.

Current limitations

Clear boundaries make the next milestone measurable.

Explicit one-shot capture

The current GUI captures exactly one frame after the user selects a game window and starts a scan. It does not watch continuously or detect battles automatically.

No live overlay

The application renders an output image after analysis. It is not an in-game or always-on overlay.

OCR still under development

The private baseline selects the next experiment; it is not a release threshold or independent holdout.

Internal portable build

The Windows package path is validated in CI but remains unsigned and is not publicly distributed.

No deployed backend

There is no production BlitzPredict cloud, subscription service, user account system, or mobile application.

Policy review remains

Any live-use release must still be checked against Wargaming policy and applicable platform rules.

Responsible scope

Useful context without hidden access to the game.

BlitzPredict is designed around visible loading-screen information, public player statistics, conservative identity handling, and explicit evidence limits.

  • No game-client code injection, process memory reading, packet interception, or gameplay automation.
  • Only unambiguous exact account matches may contribute statistics to the HUD and team sample.
  • Committed benchmark data is synthetic; private development screenshots and audit outputs stay outside Git and CI.
  • Audit output is aggregate-only and excludes nicknames, screenshots, crops, paths, account IDs, coordinates, and per-row results.
